## Architecture and behavior

- Reuse current schemas, shared RHF widgets, TanStack Query provider and feature service/repository layers. Keep component props/render-only types and generic transport utility types as TypeScript when they do not describe independently validated data.
- Place Zod schemas with their owning feature. Derive input/output/request/query/response types using z.input/z.output/z.infer. Retain domain import paths as type aliases/re-exports where they serve existing callers; eliminate duplicate field declarations. Form and request schemas must be distinct when their shapes differ, such as RHF arrays of objects versus request arrays of IDs. Do not blindly replace a form schema with partial request validation.
- Parse request/query data at the service boundary before existing serialization and parse API response data/pagination at the repository boundary. Do not globally alter HttpHelper or require invented envelope fields: the backend envelope is status/data/msg/err, while old portal mocks sometimes add statusCode. Preserve transport/error handling and endpoint signatures unless updating every caller in the ticket.
- Derive response shapes from current backend DTOs/factories and active UI consumers, rather than outdated portal interfaces. JSON dates are strings, not Date objects: do not add automatic Date coercion. Update fixtures and date-bearing callers accordingly. Preserve real optional/nullable fields; do not require legacy fields absent from the current DTO. Course prerequisites are summaries rather than recursively complete courses. Master data currently returns roles, typeCourses, tagsGroups, tags, prefixes and newsCategories. Keep all backend files unchanged.
- Each feature client.ts becomes the public browser data-hook entrypoint with private service/repository instances. Put query/mutation hooks there; put form/controller hooks under the feature's hooks directory. Components should no longer import exported service instances or implement async API orchestration. All affected cross-feature callers must be migrated in the same ticket so each change remains green. Avoid import cycles between client.ts and hooks.
- Queries use stable feature/resource keys including relevant IDs and filters, and are enabled only when their required inputs are ready. Preserve existing no-retry behavior for auth/session validation. Mutations do not automatically retry. Invalidate affected browser queries on success; preserve existing confirmation/navigation timing and SSR router.refresh behavior. Do not replace server-rendered list props with duplicate client queries.
- Form/controller hooks own RHF state, field arrays, default/reset mapping, payload conversion, nontrivial file/crop/reorder state, submit/cancel/confirmation state and loading/error logic. JSX/render helpers and trivial DOM event adapters can stay in components. Use feature-specific hooks, not a universal form framework. List controller hooks own substantive URL/search/pagination/delete logic; retain current debounce and query-parameter semantics.
- Mutation failures must reject rather than be swallowed by catch-and-return-null. Remove such catches at their source and update contracts/callers/tests. Legitimate null success (student batch import) and null absence/session results remain supported and distinguishable from failure. Preserve HttpError identity/status when present.
- Auth must fetch/validate the current server session before granting admin access, even if persisted state or query cache contains an admin. Share session loading without exposing stale private data, clear/cancel cached private queries when login changes identity or logout succeeds, and keep existing role/redirect behavior. Student profile loads only after the current user is known.
- Keep business validation unchanged: do not tighten studentCode lengths, URL protocols, news date ranges or focal-point ranges in this refactor. Preserve existing translated messages and form behavior. Fix only defects required to make the migrated hook/error/data boundary function correctly, with focused regression coverage.
- Do not fix carousel behavior or revive unused legacy news-information routes. Adapt remaining compiled callers as necessary. Delete code only when this migration makes it unused, after verifying callers.
